# MGDS RFC process

RFCs define changes whose consequences extend beyond one implementation. Use an
RFC for normative terminology, schemas, registry entries, compatibility rules,
security or privacy boundaries, evaluator authority, benchmark scoring, or
governance.

Copy `0000-template.md`, allocate the next number after acceptance, and include:

- motivation and user-visible contract;
- exact normative changes and compatibility impact;
- security, privacy, authority, and abuse analysis;
- fixtures, conformance clauses, migration, and rollback;
- alternatives and unresolved questions.

The discussion period is at least seven calendar days. Acceptance requires two
maintainer approvals, no unresolved security objection, and an implementation
owner. Emergency security changes may use an embargoed RFC and publish it with
the fix. Rejected and withdrawn RFCs remain visible.
