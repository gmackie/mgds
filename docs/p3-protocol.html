P3 clean-room adapter protocol

P3 proves that an unaffiliated Unity team can implement the public MGDS contract without private schemas, source, credentials, or implementation coaching. Tooling is complete; the gate remains open until a real external submission is replayed and accepted.

Inputs

  1. Use only a tagged public specification, SDK, schemas, fixtures, benchmark task, and conformance commands.
  2. Pin the adapter source revision, Unity version, host, evaluator identity, and public submitter key.
  3. Record specification questions as public issues. Private MGDS or GMacko material is prohibited.

Required proof

The adapter must pass T0 and the published representative T1 task. A submission manifest uses mgds.p3-submission/v1 and binds the T0 report hash, task evidence hashes, event-ledger head, toolchain, host, evaluator, privacy classification, and exact adapter revision.

Portable bundle and replay

  1. Create an artifact index mapping portable bundle paths to local evidence files.
  2. Keep the Ed25519 private key owner-only and outside the repository.
  3. Run pnpm p3:build -- --manifest … --artifacts … --authority … --private-key … --output ….
  4. Give the bundle and public key to an independent verifier.
  5. Replay with pnpm p3:replay -- --bundle … --public-key …. Replay checks bounded bytes, portable unique paths, every artifact hash, privacy rules, manifest binding, and the signature.

Acceptance gate: P3 is complete only after an unaffiliated implementation’s real signed bundle returns status: verified and its T0/T1 evidence is independently accepted. Repository fixtures or self-signing do not satisfy this gate.
