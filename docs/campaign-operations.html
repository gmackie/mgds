Sealed P2 campaign operations

The campaign is 90 immutable slots across three hosts, two harnesses, three seeds, and five repetitions. Each host runs only its own shard, one Unity editor at a time.

Prepare and resume

  1. pnpm campaign:plan seals task and environment bytes.
  2. pnpm campaign:shard:status -- --plan artifacts/campaigns/p2-plan.json --checkpoint <host-checkpoint.json> initializes or resumes the exact local-host shard.
  3. For the reported slot, create a disposable workspace from the sealed source and run pnpm campaign:harness -- --plan … --slot … --task … --harness codex|claude-code --workspace … --model … --output ….
  4. The harness receives only public task material and produces a bounded non-authoritative record. Raw model output is discarded.
  5. An independent evaluator collects compile, tests, event-ledger, PNG screenshot, and player-build bytes, replays them, forms mgds.campaign-evidence/v1, and signs the shared campaign payload. Only then append the run and checkpoint the slot.

Safety invariants

Harness environments are allowlisted; shell interpolation is disabled; execution has time and output limits; descendant processes are terminated; keys stay in owner-only regular files outside the repository; checkpoints are atomic; foreign and duplicate slots fail closed. A harness never declares its own verdict.

Soak and completion

At least one independently attested run for every host/harness pair must run for 240 minutes. All 90 slots must be valid with 100% T0 pass rate, 100% seeded agreement, zero orphan processes, and zero unknown workspace states.
