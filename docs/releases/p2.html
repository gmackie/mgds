MGDS P2 research-preview candidate

The engineering candidate contains the public protocol, implementations, benchmarks, hardening layers, harness contracts, and documentation. It is not a signed P2 release until independent review, cross-platform Unity campaign evidence, immutable artifact identities, and release-authority signing are complete.

Machine-enforced gate

pnpm release:p2:check requires a clean checkout matching MGDS_RELEASE_SOURCE_DIGEST with every source-bound engineering and campaign input tracked, regenerates the sealed campaign plan from repository bytes, resolves and replays the bounded, schema-valid, privacy-safe evidence bundles named by results/p2/evidence.json, evaluates results/p2/runs.json, cryptographically verifies the local host artifacts named by results/p2/host-t0.json against that source digest, hashes the actual review report and verifies its release-target signature, and checks the version-specific signing record. The command exits non-zero for any missing, malformed, unverified, or unresolved input. A claimed campaign summary, an attestation URL, an asserted replay flag, or an edited candidate status cannot promote the release.

The evaluator registry is a source-bound campaign input. Review approval, the review report, reviewer and release-authority public-key registries, and the final signing record are detached under artifacts/release/p2/, which is ignored by version control. This prevents review and signing from changing the source commit they approve. Their exact bytes and trust fingerprints are still bound into the review target and final release subject. The committed files in security/ and versions/ are pending templates only.

Appointment and insertion of Ed25519 public keys are governance actions. Trusted key fingerprints must arrive through the documented out-of-band environment variables, and private signing material must never enter this repository.
