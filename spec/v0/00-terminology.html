MGDS v0 research preview · normative vocabulary

Terminology

The key words MUST, MUST NOT, REQUIRED, SHOULD, SHOULD NOT, and MAY are normative requirements. MGDS defines a Unity-specific game-development environment; it does not redefine Unity products, model harnesses, or transports.

System roles

Controller
The host process that resolves policy, submits procedures, tracks jobs, coordinates leases and budgets, and assembles evidence. The controller is outside the Unity process.
Unity adapter
The conforming implementation inside or adjacent to a Unity Editor that maps MGDS capabilities onto Unity APIs. It is the authority for authoring/import state, not evaluation truth.
Player probe
An optional, bounded interface compiled only into development players. It exposes declared runtime observations and actions; it is absent from release players.
Task harness
The process that supplies an immutable task bundle, starting snapshot, policy profile, fixtures, budgets, and terminal conditions.
Evaluation sandbox
An isolated process that receives sealed task inputs and content-addressed evidence, executes visible and hidden assertions, and produces the authoritative validity verdict and scorecard.
Artifact store
A content-addressed store for immutable snapshots, events, logs, captures, test reports, profiler data, builds, attestations, and results.

Managed resources

Project workspace
The durable root resource: one isolated Unity project plus its repository and artifact scope.
Resource
A typed object addressed by an opaque MGDS identifier. Resources include projects, editors, players, scenes, assets, objects, build targets, test runs, and package-provided subsystems.
Design-time identity
A durable identity derived from project data, such as an asset GUID and file identifier.
Runtime handle
An opaque, generation-scoped identity that becomes invalid when its owning player or play session ends.
Artifact
An immutable byte sequence identified by media type, byte length, digest, producer, privacy class, and provenance.

Behavioral contract

Capability
A versioned declaration of one observable or actionable behavior, including schemas, resources, preconditions, effects, invariants, risk, authority, idempotency, timeout, cancellation, bounds, and artifacts.
Procedure
A typed invocation of a capability or an approved deterministic composition of capabilities. A procedure has immutable arguments and an idempotency key.
Job
The asynchronous lifecycle record for a submitted procedure. A job moves only through the transitions defined by the normative job state machine.
Observation
A bounded snapshot, causally ordered typed event, or immutable artifact that declares source, freshness, units, coordinate frame, correlation, and truncation.
Profile
A named set of requirements layered on core conformance, such as semantic state, multiplayer, performance, robustness, visual, audio, or accessibility.
Instrumentation level
L0 is generic Unity access, L1 adds the MGDS semantic package, and L2 adds a project/domain adapter.

Authority and proof

Policy grant
A deny-by-default authorization bound to project, resource scope, mutation channel, risk ceiling, duration, and budget.
Approval
A time-bounded authorization bound to an exact procedure digest, arguments, expected effects, scope, and budget.
Lease
Exclusive, expiring ownership of a contention-sensitive resource such as Editor mutation, scene serialization, package resolution, build target, or play-mode control.
Evidence bundle
A content-addressed run manifest, append-only event ledger, artifacts, evaluator identity, result, and optional signature.
Environment conformance
A T0 verdict about an adapter/environment implementation, reported separately from model-agent performance.

An MGDS specification or implementation MUST NOT use “Unity CLI” as an MGDS component name. It MAY identify Unity CLI as one host transport. The same rule applies to Unity Pipeline and MCP: integrations are named explicitly and are not the normative MGDS contract.
