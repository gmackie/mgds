MGDS v0 research preview · normative architecture

Unity environment architecture

MGDS standardizes the complete Unity inner development loop: inspect, modify, compile, play, interact, observe, test, profile, build, and prove. The schema and lifecycle contract are canonical. CLI, MCP, and language SDKs are projections and MUST preserve the same authorization, job, error, and evidence semantics.

Durable root and resource graph

The Project workspace is the durable root. Editors, players, test runners, build workers, build targets, scenes, assets, objects, and package-defined subsystems are subordinate typed Resources. All externally visible resource identifiers are opaque and project-scoped. Raw paths are adapter-private implementation details.

Required components

Controller

Loads the run and policy manifests, negotiates versions, acquires leases, submits idempotent procedures, enforces budgets, tracks jobs, and records the append-only event ledger. It MUST NOT author evaluator verdicts.

Unity adapter

Runs at the Unity API boundary. It discovers capabilities, resolves resource identities, evaluates preconditions, executes typed Editor operations, and emits bounded observations. Experimental Unity CLI/Pipeline details MUST remain behind its compatibility module.

Player probe

Provides bounded runtime observations and declared actions in development players only. The probe MUST authenticate the local controller, enforce profile limits, and invalidate runtime handles on generation changes.

Task harness

Supplies immutable start state, task, fixtures, policy, budgets, required artifacts, visible assertions, and terminal conditions. Hidden assertions remain sealed for the Evaluation sandbox.

Evaluation sandbox

Runs independently from agent-controlled code. It verifies input and artifact digests, executes evaluators, applies evidence authority, and signs the validity verdict and scorecard for published results.

Artifact store

Persists immutable, content-addressed artifacts and provenance. It rejects path escapes, partial writes, digest mismatch, unbounded payloads, and privacy classes prohibited by the active policy.

Capability tiers and mutation channels

Core Unity capabilities cover discovery, project/assets, scenes, objects/components, compile, play, deterministic input, logs, captures, tests, coverage, performance, and builds. Optional profiles cover semantic state/events/assertions, multiplayer, robustness, visual, audio, and accessibility evidence.

Mutations MUST identify one channel: repository patch, typed Editor operation, or player-input action. Arbitrary shell, package installation, and C# evaluation are not baseline capabilities and require an elevated, sandboxed profile.

Run data flow

  1. The Task harness sends an immutable task and run manifest to the Controller.
  2. The Controller negotiates capabilities and resolves deny-by-default policy.
  3. The Controller acquires leases and submits an idempotent Procedure to the Unity adapter.
  4. The Unity adapter reports job progress and writes bounded observations to the Artifact store.
  5. The Controller seals the evidence bundle without adding evaluation claims.
  6. The Evaluation sandbox verifies digests, executes assertions, and emits the authoritative result.

Authority ordering

When evidence conflicts, authority is: isolated evaluator assertions; semantic state and typed events; compiler, test, and build output; bounded visual/audio evidence; model-agent narrative. Lower-authority evidence aids diagnosis but cannot overturn higher-authority failure.

Conformance boundary

T0 certifies the adapter/environment independently. T1–T3 benchmark model harnesses against a named immutable conforming environment. A combined result MUST preserve both identities and MUST NOT convert an environment failure into an agent score.

Normative non-goals

MGDS v0 does not claim cross-engine support, MHS compatibility, store or cloud deployment authority, console certification, machine authority over creative quality, or a required hosted service. Release players MUST NOT contain the reference Player probe.
