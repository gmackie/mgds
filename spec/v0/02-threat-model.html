MGDS v0 research preview · normative security model

Threat model

Boundary: conformance means the declared controls are implemented and tested. It does not make arbitrary agent-generated code safe, certify release players, or remove the need for platform sandboxing and human review.

Protected assets

  • Repository source, Unity assets, serialized scenes/prefabs, package locks, VCS history, and unrelated user work.
  • Credentials, licenses, signing material, private endpoints, identity, prompts, transcripts, and customer/project data.
  • Editor/player processes, build workers, host CPU/GPU/memory/disk, network, ports, and Unity seats.
  • Run manifests, policy grants, approvals, leases, event ledgers, artifacts, evaluator inputs, results, and signatures.
  • Published specification, packages, benchmark fixtures, hidden task confidentiality, and result comparability.

Threat actors

  • A model or harness that is confused, over-broadly instructed, compromised, or intentionally adversarial.
  • Malicious or vulnerable project code, Unity package, importer, native plugin, evaluator, adapter, or dependency.
  • A concurrent local process or second agent racing the same workspace or Editor.
  • A result publisher attempting to alter evidence, hide failures, substitute evaluators, or misstate environment identity.
  • An external network peer attempting discovery spoofing, token theft, replay, injection, or resource exhaustion.

Threat catalog

MGDS-T01 — Ambient authority and credential disclosure High

A tool inherits host credentials, filesystem reach, or unrestricted networking, or emits a secret into logs/evidence. Required controls are deny-by-default capability grants, brokered short-lived opaque secret handles, allowlisted destinations, environment scrubbing, redaction before persistence, and negative leakage fixtures.

MGDS-T02 — Workspace and privacy leakage High

Evidence contains raw local paths, identity, transcript text, unrelated source, or unbounded project graphs. Required controls are project-scoped opaque identifiers, structured privacy classes, bounded projections, path normalization, publication preview, and zero-retention defaults for prohibited data.

MGDS-T03 — Command, code, and path injection High

Untrusted text crosses into shell, C# evaluation, package installation, file paths, terminal output, or Unity import hooks. Baseline MGDS excludes arbitrary shell/eval/package capabilities. Elevated profiles require argument-vector execution, path confinement, allowlists, sandboxing, terminal escape removal, resource limits, and exact approval.

MGDS-T04 — Stale approval, replay, and concurrent mutation High

A changed procedure reuses an approval, a retry executes twice, or concurrent writers corrupt state. Controls are canonical procedure digests, expiry, idempotency keys, terminal result immutability, resource leases, optimistic precondition hashes, monotonic event ordering, cancellation, and verified recovery state.

MGDS-T05 — Dependency and adapter supply chain High

A mutable package, spoofed namespace, compromised generator, or drifted Unity compatibility layer changes behavior. Controls are immutable pins and lockfiles, publisher provenance, package allowlists, license/vulnerability metadata, generated-code drift checks, isolated builds, signed releases, and conformance reruns after every dependency change.

MGDS-T06 — Evaluator and evidence tampering High

An agent modifies hidden assertions, substitutes artifacts, omits events, or forges a passing report. Controls are evaluator isolation, sealed inputs, content-addressed artifacts, append-only ledger hashing, evaluator identity, signed published results, independent replay, and invalidation on any digest mismatch.

Required controls

  1. Every externally supplied document is schema-validated before use and bounded before model exposure.
  2. Transport access grants no authority. Policy is deny-by-default and approvals bind exact immutable procedures.
  3. Mutations declare risk and recovery level. Adapters may raise risk but never lower it.
  4. Secrets and network are brokered capabilities. Raw values never enter manifests, logs, prompts, or evidence.
  5. Jobs enforce deadlines, cancellation, budgets, heartbeats, lease expiry, and owned-process cleanup.
  6. Artifacts are redacted, bounded, written atomically, hashed, and verified before evaluation or publication.
  7. The evaluator is isolated from agent-controlled writes and is the authority for benchmark validity.
  8. Release gates include negative authorization, recovery, privacy, supply-chain, and tampering tests.

Residual limitations

  • Unity project code and importers execute native and managed behavior; OS/container isolation remains necessary.
  • Unity licensing, package registries, compilers, graphics drivers, and platform toolchains introduce external trust.
  • Visual, audio, accessibility, and creative judgments can expose media and require separate human review.
  • Deterministic seeds do not guarantee bit-identical physics, graphics, audio, or performance across hardware.
  • The research preview has no claim over store submission, production credentials, console platforms, or release players.
